## 开发约定

- 新的好友/在线状态外部调用不得直接放到频道线程。进程内、跨进程遵守同一后台入口；远端同步 RPC 在游戏线程会直接报错。
- 好友功能仍为现有的本频道在线名字查找和列表协议范围，完整好友申请/列表等玩法按游戏路线继续补齐。本轮没有扩展好友玩法。
- Presence 队列容量 8192，好友队列容量 4096，计入正在执行的任务；失败和拒绝明确记录日志，后续任务继续执行。该事件链沿用非可靠投递语义，不承诺协调者断链期间零丢失。
- 插件贡献必须通过宿主接口或 `context.contributions()` 注册，后台任务使用 `context.execute(executor, task)`，自有资源使用 `context.track(handle)`。绕过上下文自行创建线程/回调的插件不满足卸载契约。
- 插件在途排空、stop/句柄清理分别最多等待 5 秒。超时保留原插件和未完成任务，拒绝装入同 ID 新版；再次卸载继续等待或重试失败清理，不取消正在运行的代码后强行释放加载器。
- 存档配额由 `twinkle.persistence.save-capacity` 配置，默认 128，限制正在捕获/等待写入/正在落库的快照数。超载不阻塞频道，不丢弃待补存的离线角色；在线脏角色在后续 Tick 补存。
- 定期补存包含离线失败角色；关闭 Worker 前先停接入、排空后台 IO 和存档，再关闭频道执行器。补存失败时停止关闭流程，保留可恢复的运行态。
- 存档指标：`save.capacity`、`save.deferred.characters`、`save.failed.characters`、`save.rejected.total` 和既有写队列深度。同步控制面等待超时会失败返回，不能把超时当作事务已取消或已成功。

## WZ 发布约定

- 源目录下 `.twinkle-snapshots/<SHA-256>/` 是运行时生成的只读代际文件。旧频道或旧目录尚在使用时不得覆盖、修改或删除缓存；历史缓存可在进程停止后统一清理，不进入 Git。
- 准备时复制文件并复核源内容；发现更新中途源目录变化就拒绝该次准备。应先完成源文件发布，再调用重载。
- 集群先确认所有目标 Worker 的候选摘要相同。任一 Worker 准备失败或摘要不一致，均不进入发布阶段。RPC 超时重试复用已准备快照；摘要不一致时撤销未发布的候选，修正源文件后重新预检。
- 发布按频道推进，不提供全服同时切换或自动回滚。部分发布失败时保持失败频道旧版，再次重载重试原候选；已成功频道/Worker 不重做。
- 排队等待的频道发布屏障超时会取消；已开始执行的发布可能完成，因此保留候选并通过同候选重试确认结果。集群 RPC 超时显示 UNKNOWN，不显示成功。
- 成功响应包含 `digest`、`versions`、`failures`。控制台遇到非空 failures 显示失败目标，继续操作会重试同一轮发布。
- Worker/管理进程崩溃后的跨进程发布事务不持久化恢复；重启属于完整资源初始化，需先确保各 Worker 源目录一致。

本轮改变宿主及插件 API 的装配能力，首次应用需要完整升级并重启，不属于只换业务 JAR 的发布。未执行生产部署或生产数据库操作。
