| 同一换线链路的冻结状态 | 队伍 Tick 曾把 `stateTransfer` 当作离线，慢存档或失败恢复会误解散队伍。现在只清理真正失去会话的成员；冻结期间其他成员引发的队伍变更每连接合并为一份待同步状态，恢复后补发完整结果。 |
| 北斗 `d10b544b8` / datas-server `f86733df1`：资源重载与并发读取 | 本服尚未接入怪物掉落表，不能声称修复其掉落算法。对现有 WZ 链路发现同类换代窗口：全局资源先更新、频道运行态后更新，且准备后新增对象被漏掉。已增加每频道资源视图和完整操作的读取作用域，提交时重新核验当前地图/怪物，再一起推进该频道投影与资源代际。失败频道保持旧代；成功频道不自动回滚。 |

## 当前边界

- 本批涉及宿主、状态入口及共享接口，发布仍需重启；没有完成内置 Java 整包热更新。
- WZ 改动保证已采用资源快照与频道运行态在操作边界一致，不承诺全服同一瞬间换代。多频道部分失败、管理状态汇总、跨进程发布恢复还需继续完善。
- 地图和部分 XML catalog 仍从文件延迟解析；资源视图并不等于底层文件的不可变制品。原地修改尚未缓存的 XML、准备阶段解析延迟和制品发布协议仍需治理。
- 跨进程 Presence 的会话代际与失败补偿、社交同步 IO、插件在途回调/卸载、慢数据库下存档队列容量等继续按路线图跟踪；本批不代表全部历史并发问题已解决。
