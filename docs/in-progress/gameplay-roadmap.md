# 游戏功能推进（2026-09-06）

本路线以玩家实际操作为入口。历史 M0–M6 的完成状态代表基础架构里程碑，不代表所有 v83 玩法已经可用。打包发布脚本已按要求删除，当前优先完善游戏功能。

## 参考边界

北斗作为行为和协议字段的核对来源，不复制其 Java 实现、脚本、SQL、商品列表或资源文件。新增实现使用 Twinkle 的角色状态、版本门、频道运行态和封包写入器。测试 WZ XML 独立构造，商店初始配置独立编写。

本次核对范围：地图切换、NPC、背包更新、掉落、商店、任务、AP/SP、普通自身 Buff、组队消息的字段顺序。引用位置为北斗对应接收 Handler、PacketCreator 以及 WZ 的字段含义；协议相关类已注明来源。开发时外部 WZ 仍通过 `twinkle.wz.path` 读取，不将参考仓库内容带入本仓库。

## 本轮已实现的服务端范围

以下“已实现”指代码已接入频道并有自动回归验证；尚未完成真实 v83 客户端联调。

| 功能 | 本轮落地 | 当前边界 |
|---|---|---|
| 换地图与传送门 | 服务端选目标及落点、距离校验、进图对象发送、死亡回城、NPC 脚本宿主真实换图 | 普通 WZ 目标门；脚本门、地图进入脚本尚未接通 |
| 背包与物品 | 正槽移动、拆分、合并、交换、普通恢复药、完整实例丢弃与拾取、掉落过期清理 | 不含穿脱装备、怪物掉落、金币掉落、宠物自动拾取 |
| NPC 商店 | 真实地图 NPC 对象、服务端商品配置、买卖、金额及容量预检、换图后旧商店失效 | 普通堆叠商品；装备商品、飞镖/子弹充值待做 |
| AP/SP | 手动和自动分配四维 AP，SP 扣点、职业分支、前置技能、技能等级上限、龙神 SP 编码 | HP/MP AP、新手专用 SP、技能书和升级/转职发点待做 |
| 基础任务 | 接取、放弃、完成、NPC/等级/职业/物品/前置任务/击杀检查，物品和金钱奖励原子提交，击杀进度回包 | 不含脚本任务、随机/选择奖励、装备奖励、时间条件；未知条件或奖励拒绝执行 |
| 自身 Buff | 圣甲术 `1001003`、魔法盾甲 `2001003`、集中术 `3001003` 的 WZ 等级读取、扣蓝、重施、取消、死亡及到期清理 | 仅这三个普通自身增益；完整战斗属性计算、范围增益、召唤和跨频道 Buff 保留待做 |
| 同频道组队 | 创建、邀请、拒绝、加入、退出、解散、踢人、转交队长、地图/等级刷新、离线清理 | 临时频道队伍，最多六人；离开频道即退出，队长离线解散；无经验分配、跨频道保队、队伍门 |

同时修复两个基础问题：各频道不再共用 WZ 缓存中的地图运行对象；NPC 对话不再把对象 ID 当成模板 ID。药水改为精确消耗请求槽位，并用正确的 HP/MP 状态包响应。普通奖励/购买的物品不会堆进带不同期限、主人等属性的旧实例。

商店配置：`twinkle.gameplay.shop-path` 可指向自有 properties 文件，格式为 `NPC模板ID=物品ID:单价,物品ID:单价`。未配置时使用 `channel/src/main/resources/gameplay/shops.properties`，当前只有独立编写的药水示例店。

## 接下来按这条路线继续

1. **多人地图可见性**：补玩家入图、离图、外观、Buff 与位置同步。目前已有移动/攻击广播，但缺玩家生成与移除报文，必须优先补齐。
2. **装备穿脱与属性**：读取 Character.wz 装备定义，校验职业/等级/部位，装备交换、基础属性与装备属性汇总。
3. **战斗与死亡**：区分物理/魔法技能，校验技能等级、消耗、目标和命中次数；怪物伤害、受伤、死亡、复活、异常状态统一结算。
4. **击杀收益与升级**：怪物经验/金币/物品掉落配置，掉落归属，经验阈值、升级和 AP/SP 发放。当前攻击入口仍有徒手伤害简化，任务经验只记数值，不能标为完整升级链路。
5. **转职和技能成长**：新手技能点、转职任务、技能书、洗点、更多主动技能与 Buff 的实际战斗效果。
6. **地图及任务脚本**：自研 portal/quest 宿主，地图进入/离开触发，限时地图，条件门，选择奖励和重复任务。
7. **社交补全**：好友请求/确认/完整列表、好友上下线、组队 HP/经验共享、跨频道队伍属主与恢复、公会。
8. **更多长期玩法**：仓库、玩家商店、宠物、掉线重连、活动/副本与每日任务。按上述基础闭环完成后推进。

每项先明确服务端规则与协议，再实现独立代码与回归；以真实客户端操作结果验收，不以新增 Handler 数量判断玩法完成。

## 验证与验收

新增自动回归覆盖：

- 非法/远距离传送不改变地图；频道地图运行态相互隔离。
- 并发拾取只能成功一次；背包满、地图不符时掉落仍可被合法拾取。
- 指定槽位用药；物品拆分/交换保留实例属性；购买金额溢出及容量不足不扣款。
- 商店会话、报价、NPC 距离校验。
- 任务条件、服务端击杀进度、满背包失败回滚、重复完成不重复奖励。
- AP 超额分配及跨职业 SP 拒绝；自动 AP 整体校验。
- Buff 伪造等级、魔力不足、冷却、覆盖、取消和过期。
- 无邀请/过期/换连接邀请不能加入；六人上限、队长权限和断线解散。

后端完整验证命令：`mvn -B clean verify`（在 `twinkle-server/` 执行）。测试不需要访问生产服务器，也不依赖参考项目源码或真实客户端。

真实客户端待验收：两名角色登录同频道后，对普通门、背包拖动/丢弃/拾取、药水、商店买卖、加点、基础任务、三个自身 Buff、组队流程逐项录包验证；再补频道切换、满背包、死亡和断线场景。当前未把这一环节标为完成。
