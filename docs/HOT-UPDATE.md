# 模块热重载对照表

> **这是改造后的模块目标，不是当前已实现能力。** 当前内置 Java 修改仍需重新打包、重启；下列业务模块尚待拆分和接通热重载。

## 业务实现模块：支持兼容变更热重载

以下名称为拟拆分的模块名，目前尚不存在。

| 目标模块 | 从现有模块拆出什么 | 改造后能热重载吗 |
|---|---|---|
| `game-logic` | `domain-game`、`channel` 中的战斗、技能、掉落、任务、交易、活动等玩法 | **能** |
| `login-logic` | `login` 中的登录校验、账号准入、选角等业务规则 | **能** |
| `admin-logic` | `http-api` 中的管理用例、业务校验、权限判断规则 | **能** |
| `query-logic` | `persistence` 等模块中的业务查询与数据组合逻辑 | **能** |
| `coordinator-logic` | `coordinator` 中的频道选择、分配等业务策略 | **能** |

## 运行底座与共享契约：重启或迁移更新

| 模块/职责（拆分后保留） | 更新方式 |
|---|---|
| `core`、`bootstrap`：启动、DI、执行队列、调度与加载器 | **重启** |
| `net-netty`、`net-packet`：连接、加密、编解码与协议基础 | **重启**；协议变化另做兼容检查 |
| `domain-game`、`plugin-api` 等：稳定状态类型、共享接口与 DTO | **重启**；状态结构变化还需迁移评估 |
| `channel`、`login`、`coordinator`、`http-api`：状态持有、会话、传输适配与稳定调用入口 | **重启**；其中的业务实现按上表拆出 |
| `persistence`：连接池、事务与存档基础、实体映射、数据库结构 | **重启或数据库迁移**；业务查询按上表拆出 |
| `domain-script`、`wz-provider`：脚本引擎/宿主契约、资源加载基础 | **重启**；外部脚本和资源见下表 |

**使用规则：** 只改已完成改造的业务实现模块，且不改变共享接口、状态及协议，可以热重载；涉及运行底座或契约，按上表升级。业务模块增加私有方法、辅助类不等于修改共享接口；跨模块一起修改时，需作为兼容的一组发布并验证。

**划分原则：** 不因代码现在位于 `login`、`http-api` 或 `persistence`，就认定它永远不能热更。其他模块中的兼容业务实现也可按同一原则拆出，并同步本表。

## 外部内容：当前能力

| 其他内容 | 现在能热重载吗 |
|---|---|
| 外部 JS 脚本 | **能**；新调用生效，进行中的对话使用旧源码 |
| 外部 WZ XML | **部分能**；限已接入的资源与运行态更新 |
| 配置中心动态值 | **已接入的配置项能**；启动参数不包括在内 |
| 外部插件 JAR | 有装卸机制，可靠在线热重载尚未完成验证 |
| `twinkle-web` 前端 | 不能；当前嵌入主 JAR，需要重新构建、重启部署 |

机制说明见 [架构文档](../ARCHITECTURE.md)。本表在模块改造后同步更新。
