## 0. 范围、方法与结论摘要

### 0.1 审计对象与边界
- 仓库处于**骨架期**：工程代码未启动，可审计的实质对象为架构文档与既有配置（`ARCHITECTURE.md`、`CLAUDE.md`、`.gitignore`、模块规划）。
- 本次不针对具体实现做代码级测试，而是对"设计是否预埋安全门槛"做缺口审计，并给出各里程碑**可验收**的安全门槛。
- 威胁模型以**冒险岛 v83 私服服务端**这一特定场景为锚（客户端协议公开、私服常成为攻击目标），兼顾通用服务端安全。

### 0.2 总体结论（Top 发现）
1. **安全在架构中为零存在**：全文无安全章节，红线 17 条无一涉及认证/授权/注入/密钥/日志脱敏。安全不是"默认具备"，而是"从零补"。
2. **鉴权整体缺失**：第三方 `/api/v1` 仅"限流+版本化"无鉴权（1.2 五大目标表）；admin Web 控制台 / 运维 API 无任何鉴权要求（4.2、4.6）；跨进程帧无身份（4.5）。
3. **注入高风险面被明确允许存在**：`Character` 存档复杂联写保留原生 SQL 兜底（红线 7）、"复杂原生 SQL 用两库公共子集语法写"（6.2），但全库未强制参数化、未禁止 `${}`/字符串拼接。
4. **插件信任边界=全权且无供应链防护**：7.2 明确"插件可访问一切数据"，无签名、无 manifest 权限、无沙箱。恶意插件 = 全量数据失控。
5. **密钥与配置管理空白**：`.gitignore` 未忽略任何含密钥的配置文件；架构未要求密钥外部化；DB 密码 / AI Key / admin 密码落点未定义，存在明文入仓风险。

> 以上 5 条为最高优先级，必须在 M0（缺口 2/3/5 的部分）与 M1/M3/M4（缺口 1/2/4）分别关门。

## 1. 威胁模型（Threat Model）

> 分类列出私服服务端核心威胁，每条给**简述 + 典型攻击面**，并标注与现有架构的关联。

### T1 协议逆向与封包篡改
- **简述**：v83 协议 `RecvOpcode` 字节级不动（红线 1）、加解密原样移植（1.2 五大目标表）。v83 的客户端/服务端密码学（MapleStory 自定义异或+AES 类变换）在私服社区**已公开、属混淆而非安全边界**。攻击者在客户端侧注入或抓包重发，可发起越权操作。
- **典型攻击面**：WPE / 封包工具篡改出站包；凭空加物、瞬移、改属性、刷币；伪造/重放 `RecvOpcode`；利用已知 opcode 枚举未实现 handler。
- **架构关联**：4.5 帧格式 `[帧头|消息类型|消息ID|负载]` 无完整性校验；HandlerRegistry 可 register/replace（1.2）但无白名单/长度/校验和约束。

### T2 认证与会话安全
- **简述**：账号密码存储与登录会话机制在架构中**未定义**。v83 客户端登录含 PIC/PIN 流程，但服务端密码哈希、token 签发、会话时效、防重放均未规定。
- **典型攻击面**：明文/可逆存储密码被拖库即失陷；会话/token 劫持后冒用；登录阶段重放攻击；撞库/爆破（无失败限频）；中间人（明文信道）。
- **架构关联**：login 角色仅描述"账号校验/选角"（4.2），无加密存储、无登录限频、无会话策略要求。

### T3 GM / Admin 越权
- **简述**：admin 角色为"Web 控制台 / 运维 API"（4.2、4.6.2），负责改倍率、封禁、改配置等高危操作，但架构**无任何鉴权要求**。
- **典型攻击面**：控制台未登录可直接调用运维 API 改数据/封禁/改配置；越权使用他人 GM 会话；运维 API 被外部扫描命中。
- **架构关联**：4.6.5 配置中心"admin 控制台改配置 → 写 DB → 广播"；4.6.6 三路取数中第②路经 service 接口 RPC 可触发事务性操作（改密、封禁）——这些高危路径无强鉴权 + 审计约束。

### T4 第三方 API（/api/v1）越权与滥用
- **简述**：`/api/v1` 定位"第三方，限流+版本化"（1.2 五大目标表），但**只有限流、没有鉴权/签名/作用域**。任何能连到端口的人都可调用。
- **典型攻击面**：越权查他人角色/商店数据；刷接口（虽有限流但无身份，限流可被轮换 IP 绕过）；未签名调用伪造来源；作用域越界（本应只读却触发写）。
- **架构关联**：1.2 五大目标表明确"限流+版本化"而**未列鉴权**；2.1 选型表 Bucket4j "第三方 API" 仅限流；4.6.6 三路取数主路为"查 DB"，若 /api 直连 DB 且无作用域，越权查询风险高。

### T5 数据库注入与越权
- **简述**：DB 层允许原生 SQL 兜底（红线 7、6.2），但全库未强制参数化；DB 账号权限模型未定义。
- **典型攻击面**：`' OR 1=1 --` 类注入（经 HTTP 参数 / 插件 / 脚本拼接到原生 SQL）；`${}` 拼接或字符串相加构造 SQL；DB 账号权限过大（应用账号可 DDL/超级）；多数据源切换时方言差异点（db-dialect）被注入。
- **架构关联**：6.2 "复杂原生 SQL 用两库公共子集语法写"、红线 7 "Character 存档复杂联写保留原生 SQL 兜底"——这些路径若用 `${}`/拼接即注入；6.3 "业务代码不允许出现裸的方言差异"约束力在"方言"而非"注入"；DB 账号最小权限未提。

### T6 DDoS 与连接耗尽
- **简述**：Netty 承载客户端连接（1.2、4.5），架构未规定连接数上限、握手频率限制、空闲超时、单 IP 并发限制。
- **典型攻击面**：海量 TCP 连接耗尽文件描述符/内存（连接耗尽）；登录握手 flooding（login flood，v83 私服常见）；慢速攻击（建立连接后不发包占着）；acceptor 线程被打满。
- **架构关联**：4.5 内部通信与客户端共用 `net-netty`；无 `maxConnections` / `readTimeout` / 单 IP 限连描述；红线 6 仅要求"HTTP 与游戏 Netty 隔离 EventLoop"，未涉及连接级防护。

### T7 热更新 / 插件供应链投毒
- **简述**：插件系统信任边界=**全权**（7.2 结论 3），"插件可访问一切数据，但通过接口操作"。无签名、无 manifest 权限、无沙箱。
- **典型攻击面**：未签名/被篡改的 jar 混入插件目录即获全量数据访问；恶意插件经贡献点（PacketHandler / HTTP 路由 / 定时任务）提权或外传数据；插件 classloader 越界反射稳定层类；插件静默调用 AI Tool / 运维 API 越权。
- **架构关联**：7.2 "信任边界=全权"；7.3 核心约束只提"manifest 声明式注册""classloader 可见性边界（防 CCE）"，约束目标是**兼容性**而非**安全**；热更新 L3 逻辑热替换（5.2）与插件同套机制，故同一供应链风险。

### T8 配置与密钥泄露
- **简述**：密钥/敏感配置落点未定义，且 `.gitignore` **未忽略任何含密钥的配置文件**（当前忽略项仅 `target/`、日志、`twinkle.db*`、IDE、前端产物）。
- **典型攻击面**：DB 密码 / AI Key（LangChain4j）/ admin 密码明文写入 `application.yml` 被提交；配置中心真值在 `param_conf`（4.6.5）但密钥类不应入表；`.env` 或 secret 文件未忽略而误提交；镜像/备份带走密钥。
- **架构关联**：4.6.5 配置中心 DB 真值；2.1 AI 用 LangChain4j（需 API Key）；全文无"密钥外部化"要求。

### T9 日志敏感信息泄露
- **简述**：日志规范仅"用 log4j2 `log.error("描述", e)`，禁用 `e.printStackTrace()`"（红线 9），**未禁止打印明文凭证**。
- **典型攻击面**：登录失败日志打明文密码/账号；HTTP 中间件打 `Authorization`/API Key；AI Tool 调用打 token；异常栈包含 SQL（含参数）；日志文件权限过宽被读取。
- **架构关联**：红线 9 只管"别用 printStackTrace"，不管"别打明文"；2.1 日志 log4j2（须防 Log4Shell，版本锁定 + 禁用 JNDI lookup）。

### T10 存档篡改 / 复制 bug 被利用
- **简述**：热更新/重启场景下"迟到写""双写源"可造成复制 bug（5.3、5.5）。`5.3` 写路径"版本门"机制**推迟到 M3 才定义**，WAL 重放须幂等。
- **典型攻击面**：利用重载/重启窗口的迟到写复制物品；经"镜像"反向写（违反 4.6.6 镜像纪律）制造双写源；WAL 重放不幂等导致重复扣血/给经验；直接改 DB 文件（SQLite 单文件）伪造存档。
- **架构关联**：5.3 "写路径带版本门（M3 定机制）"——**当前未定义**；4.6.6 "镜像纪律：禁止经镜像回写"（设计约束但无强制校验）；5.5 WAL"重放幂等"为要求但未落地校验；6.2 SQLite 单文件，若文件权限/备份不当可被篡改。

### T11（补充）AI 工具越权与提示注入
- **简述**：AI（LangChain4j）经 `@Tool` 调用应用 service（第八节），"不得直踩游戏内存"已约束隔离，但**工具的作用域与授权**未定义。
- **典型攻击面**：提示注入诱导 AI Tool 执行高危操作（封禁/改配置/发币）；AI Tool 越权调用运维/管理 service；AI 上下文外泄敏感数据（日志/响应）。
- **架构关联**：第八节"AI 工具不得直踩游戏内存对象，只经 application service 接口"——隔离有，但 service 侧的**权限与人工确认**无。

### T12（补充）内部接口对外暴露 / 横向移动
- **简述**：`/internal/v1`（官网转调）、admin、coordinator 内部 RPC、跨进程 Netty 帧均**未声明绑定网络平面**。
- **典型攻击面**：admin/内部端口误绑 `0.0.0.0` 被公网扫描；coordinator 星形单点（4.6.4）被伪造 channel 上报污染定位表/消息路由；同机多进程回环被同机其他进程/容器横向利用。
- **架构关联**：4.6.4 coordinator 单点 + 静态配置地址；4.5 跨进程帧无身份；4.6.6 /internal 与 /api 同管理进程但信任级别不同却无网络平面区分。

## 3. 加固设计基线（Hardening Baseline，M0–M6）

> 每条门槛含**门槛说明 + 验收标准（可验收）**。验收标准尽量可自动化检测。
> 设计原则：**默认拒绝（deny-by-default）**、**最小权限**、**外部输入先校验后处理**、**敏感操作可审计**。

### M0 — 骨架与安全地基
1. **DB 查询强制参数化**
   - 门槛：全库 DB 访问经 MyBatis-Flex `#{}` 参数化；`${}` 仅允许在 `db-dialect` 受控处且经 Code Review；业务代码禁止字符串相加拼 SQL（含原生 SQL 兜底路径，红线 7）。新增 CI 静态规则（SpotBugs/PMD 自定义规则或正则扫描）拦截含有字符串拼接进 SQL 的方法。
   - 验收：仓库内无任何 `${}` 出现在业务 Mapper（除 `db-dialect` 白名单）；CI 流水线含 SQL 拼接扫描且失败即红；提供 1 个注入防御单元demo（构造恶意参数，断言被参数化转义）。
2. **密钥与敏感配置外部化**
   - 门槛：DB 密码、AI Key、admin 密码、内部通信预共享密钥全部经环境变量 / Micronaut `@Property` 外部化，禁止 `application.yml` 明文；提供 secret 加载门面与本地模板（占位）。`.gitignore` 追加 `*.secret.*`、`application-prod.yml`、`*.env`（如引入）。
   - 验收：默认配置模板中敏感项为空占位；CI 检查 `application*.yml` 不含疑似密钥字符串（正则：password/token/secret/key= 后接非空值）；`.gitignore` 已覆盖 secret 文件。
3. **启动参数与暴露端口收敛**
   - 门槛：所有监听（客户端 Netty、HTTP、admin、内部 RPC）显式绑定地址/端口；admin 与内部接口**默认绑定 loopback / 内网**，仅客户端与 `/api` 按部署需对外；启动日志打印实际绑定地址 + `--profile`。
   - 验收：默认配置下 admin/内部端口绑定 `127.0.0.1`；单元/集成测试断言绑定地址非 `0.0.0.0`（除非显式 override）。
4. **依赖漏洞扫描入 CI**
   - 门槛：CI 引入 OWASP `dependency-check`（或 Dependabot/Snyk，待决策）；`log4j2` 版本锁定 ≥ 2.17.1 且禁用 JNDI lookup；Micronaut/Netty 版本锁定并定期更新。
   - 验收：CI 含依赖扫描步骤，CVSS ≥ 7 阻断合并；`log4j2.formatMsgNoLookups=true` 或版本已免疫；提供依赖清单与版本锁。
5. **密码存储策略定型（设计 + 落地接口）**
   - 门槛：选定单向哈希算法（建议 Argon2id，待决策），定义 `PasswordEncoder` 接口与存储格式（含 salt + 参数）；`accounts` 表密码列只存哈希。
   - 验收：提供哈希/校验单元demo；断言明文密码永不以原值落库（扫描存储写入路径）。
6. **安全红线入 ARCHITECTURE.md（见第 4 节）**：M0 收口 G1/G2/G7/G8/G13。

### M1 — 协议 + Netty + 登录认证
1. **协议层完整性校验**
   - 门槛：包长上限校验（按 opcode 长度表，越界断连）；`RecvOpcode` 白名单（未知/未注册 opcode 立即断连）；帧校验和（独立於 v83 弱加密，防篡改）；异常包立即断开 + 该会话限频。
   - 验收：构造超长包/未知 opcode/校验和错误包，断言连接被断开且服务端不崩；提供协议校验单元demo。
2. **防重放**
   - 门槛：每会话递增序号 / 时间戳窗口，越界或重复序号断连；登录阶段同样防重放。
   - 验收：重放同一包被拒；序号回退被拒。
3. **登录安全落地**
   - 门槛：密码经 M0 哈希校验；登录失败限频（按账号 + 按 IP，Bucket4j 或同等）；连续失败触发临时锁定；登录成功签发服务端会话 token（有过期、可吊销）；会话劫持靠 token 时效 + 绑定。
   - 验收：错误密码 N 次后锁定；重放登录包被拒；token 过期后失效。
4. **连接级防护（DDoS/耗尽）**
   - 门槛：Netty `ServerBootstrap` 设最大连接数、单 IP 并发上限、读空闲超时（`ReadTimeoutHandler`）、握手频率限制（抗 login flood）；acceptor 与业务线程隔离（红线 6 延伸）。
   - 验收：超出单 IP 连接上限被拒；空闲连接被回收；压测下 fd/内存有界。
5. 收口 G9/G10/G11（部分）。

### M2 — 游戏逻辑重写（服务端权威）
1. **服务端权威校验**
   - 门槛：所有状态变更（移动速度/伤害/物品增减/属性）服务端校验，不信任客户端量；越权操作（凭空加物、瞬移、改属性）服务端校验来源与权限后拒绝。
   - 验收：构造伪造"加物/瞬移"包，断言被服务端拒绝且不计生效；parity 测试覆盖越权用例。
2. **经济/物品流水雏形**：关键物品/货币变动经可审计路径（与 M3 审计、WAL 审计 5.5 合并）。
   - 验收：物品变动可被追踪到主体与原因。

### M3 — HTTP + AI + 渐进重载
1. **/api 强鉴权 + 作用域**
   - 门槛：`/api/v1` 必须鉴权（HMAC 签名 + API Key，或 OAuth2，待决策）+ 作用域（scope）限制（只读/读写）；未鉴权不可达；限流按 `key + 路由` 细化（已有 Bucket4j 扩展）。
   - 验收：无签名调用返回 401；越 scope 调用返回 403；不同 key 限流独立统计。
2. **admin 强鉴权 + 审计日志**
   - 门槛：Web 控制台与运维 API 强鉴权（登录会话 + 角色/权限）；所有高危操作写**不可篡改审计日志**（谁/何时/什么/源 IP）；审计日志独立于业务 DB 或带防篡改。
   - 验收：未登录调用运维 API 返回 401；高危操作在审计日志留痕；审计日志无法被普通操作删除。
3. **内部接口不对外暴露**
   - 门槛：`/internal/v1` 与 admin 绑定内网/loopback（延续 M0）；公网仅暴露客户端端口与受控 `/api`。
   - 验收：从外部网络平面无法触达 `/internal` 与 admin（网络/绑定断言）。
4. **版本门机制落地（防复制 bug）**
   - 门槛：5.3 "写路径带版本门"在 M3 定义并落地：重载后旧逻辑迟到写被识别丢弃/重放；WAL 重放幂等（5.5）经测试保证。
   - 验收：构造"重载后迟到写"场景，断言不产生复制；WAL 重放 N 次结果一致（幂等测试）。
5. **AI 工具授权**
   - 门槛：AI `@Tool` 按作用域注册；高危 Tool（封禁/改配置/发币）需人工确认或强授权；AI 调用不泄露敏感上下文到日志。
   - 验收：提示注入诱导高危 Tool 被拒/需确认；审计记录 AI 操作。
6. 收口 G3/G4/G14/G16。

### M4 — 插件框架 + 热更新全通
1. **插件签名校验**
   - 门槛：插件 jar 须带签名，加载前校验信任根（自签 CA / 中心签发，待决策）；未签名/签名不符拒绝加载并告警。
   - 验收：合法签名插件可加载；篡改 jar / 无签名 jar 被拒并留日志。
2. **manifest 权限声明 + 沙箱约束**
   - 门槛：manifest 声明权限（文件/网络/数据/GM 命令）；classloader 沙箱禁止反射稳定层类桥接、限制文件/网络 IO 经白名单；权限不足的功能调用被拒。
   - 验收：未声明网络权限的插件发起外连被阻；声明权限与实际调用一致校验。
3. 收口 G6。

### M5 — Web 控制台 + 迁移 + 上线切换
1. **Web 控制台安全响应头**：CSP / HSTS / `X-Frame-Options` / `X-Content-Type-Options`；关闭 debug/actuator 端点（默认拒绝）。
   - 验收：响应头断言齐全；debug 端点默认 404。
2. **迁移安全**：migration 带 checksum 校验，禁止丢档，提供回滚预案；schema 变更经评审。
   - 验收：迁移前后数据一致性校验通过；回滚脚本可用。
3. **DB 账号最小权限**：应用账号仅 DML（按库），不授予 DDL/超级；运维 DDL 走独立账号。
   - 验收：应用账号执行 DDL 被拒。
4. **生产配置模板（默认拒绝）** + 密钥轮转方案。
   - 验收：生产模板不含密钥；提供轮转步骤文档。
5. 收口 G17。

### M6 — 分布式（跨进程安全）
1. **跨进程帧鉴权**：每进程有身份，帧带签名/HMAC（预共享密钥或 mTLS，待决策）；coordinator 拒绝未授权节点上报（注册白名单）。
   - 验收：伪造 channel 上报被拒；帧被篡改/重放被拒。
2. **内部通信 mTLS / 预共享密钥**：split 档默认启用（性能权衡待决策）；single 档回环可不做传输加密但保留帧签名。
   - 验收：未持证书的节点无法建连（mTLS 场景）；密钥轮换可用。
3. **coordinator 单点加固**：注册白名单、上报鉴权、定位表污染防护；网络层仅监听内网。
   - 验收：非法节点无法污染定位表/路由。
4. 收口 G5/G15。

## 4. 对 ARCHITECTURE.md 的修订建议

### 4.1 新增「安全章节」大纲
建议在**第十节（关键约束/红线）之前或之后**新增独立章 **「安全架构（Security）」**（建议置于第九节性能红线与第十节红线之间，编号如「九-A」或独立成章），包含以下子节：

```
安全架构（Security）
  S.1 安全分层模型
      - 网络层（绑定平面、连接防护）/ 传输层（协议完整性、mTLS）
      - 应用层（认证、授权、输入校验、服务端权威）/ 数据层（参数化、最小权限、加密存储）
      - 插件层（签名、权限、沙箱）/ 运维层（审计、密钥、日志脱敏）
  S.2 认证与会话
      - 账号密码单向哈希（Argon2id/bcrypt）、登录限频、会话 token 签发/过期/吊销
  S.3 授权模型
      - 角色（player/login/admin/GM）、作用域（scope）、最小权限；默认拒绝
  S.4 密码学基线
      - 参数化查询、哈希、签名（插件/HMAC）、内部通信 mTLS/预共享密钥
  S.5 输入校验与防篡改
      - 协议层：包长/opcode 白名单/校验和/防重放
      - 应用层：服务端权威校验，所有外部输入先校验后处理
  S.6 插件信任与供应链
      - 签名校验、manifest 权限、classloader 沙箱、加载前校验
  S.7 审计与日志
      - GM/Admin/危险操作审计（不可篡改）、日志脱敏（禁明文凭证）
  S.8 密钥与配置管理
      - 外部化（env/secret）、禁止入仓、.gitignore 覆盖、轮转
  S.9 依赖与供应链安全
      - CI 依赖扫描、版本锁定、log4j2 免疫
```

### 4.2 建议新增的红线条目（接现有 17 条之后）
> 以下条目作为"安全红线"，与现有 17 条同级、同等强制。

18. **所有 DB 访问经参数化查询**：禁止字符串拼接 / `${}` 构造 SQL；原生 SQL 兜底路径（红线 7）亦须参数化。
19. **第三方 API（/api/v1）必须鉴权 + 作用域 + 限流**：未鉴权不可达；越 scope 调用拒绝。
20. **admin / 运维接口必须强鉴权**：登录会话 + 角色权限，且仅绑定内网/loopback，不对公网暴露。
21. **插件必须签名且 manifest 声明权限**：未签名或权限不符拒绝加载；classloader 沙箱约束稳定层访问。
22. **密钥与敏感配置不得入仓库**：经环境变量/secret 外部化；`.gitignore` 覆盖 secret 文件。
23. **日志禁止打印明文凭证**：密码/token/API Key/会话/SQL 参数不得入日志。
24. **跨进程通信帧必须鉴权**：签名/共享密钥；coordinator 拒绝未授权节点上报。
25. **外部输入默认拒绝**：客户端包/HTTP/插件输入经白名单与校验后方可处理。
26. **敏感凭据单向哈希存储**：密码等以 Argon2id/bcrypt 存储，禁止明文/可逆加密。
27. **审计日志不可篡改**：GM/Admin/危险操作留痕（主体 + 时间 + 操作 + 源），禁止普通路径删除。
28. **DB 应用账号最小权限**：仅 DML，不授予 DDL/超级；运维 DDL 走独立账号。

## 5. 需用户 / 主理人决策的关键项

> 以下决策影响 M0–M6 具体落地选型，建议在对应里程碑启动前确认（不影响本文档作为基线生效）：

1. **密码哈希算法选型**：建议 **Argon2id**（抗 GPU）；备选 bcrypt。影响 M0 接口与存储格式。
2. **第三方 /api 鉴权方案**：建议 **HMAC 签名 + API Key + scope**（服务端到服务端简单可靠）；备选 OAuth2（适合第三方代表用户）。影响 M3。
3. **插件签名信任根**：自签 CA（运维签发）vs 中心化签发服务。决定供应链模型与 M4 实现。
4. **跨进程 mTLS 是否默认开启**：建议 split 档默认开、single 档回环仅做帧签名（性能权衡）。影响 M6 与 2C2G 性能红线（第九节）。
5. **密钥管理方案选型**：环境变量（最简）vs 文件 + chmod 600 vs HashiCorp Vault / 云 Secret。影响 M0/M5 与运维流程。
6. **admin / 运维接口绑定策略**：强制内网 + VPN/跳板 vs 允许公网 + 强 MFA。影响 M3 暴露面。
7. **依赖扫描工具选型**：OWASP dependency-check（自建）vs GitHub Dependabot vs Snyk。影响 M0 CI。
8. **审计日志存储与留存**：独立库/文件 + 防篡改（append-only/WORM）与留存期（合规与取证）。
