## 任务清单

### 1. 插件系统（VSCode 式）

- [x] `plugin-api` 模块：插件 SPI、SDK 版本化（插件依赖它，版本变则 API 升）
- [x] 贡献点：PacketHandler / HTTP 路由 / 定时任务 / 事件监听 / Script 命名空间 / AI Tool / 游戏逻辑系统（7 类类型定义全落地）
- [x] **贡献点从第一天版本化**（红线 13：可装卸即兼容面）
- [x] 插件声明式注册（manifest）
- [x] 插件 classloader 隔离（**可见性边界**：org.gms 一律父优先，绝不能加载/遮蔽稳定层类，否则 CCE）
- [x] 部署作用域：频道插件（战斗/任务）→ 频道进程；大区插件（公会/事件）→ 按数据属主；平台插件（AI/API）→ 管理进程
- [x] 插件经接口访问数据（信任边界 = 全权，但经接口）
- [x] 插件系统 = 热重载系统（同一套 classloader + 贡献点机制，不重复造）

### 2. 热更新 L1-L4 全通

- [x] **L1 配置**：倍率/开关/参数热改（管理端点 POST /internal/v1/config + 订阅者重读验证，ConfigCenterE2ETest）
- [x] **L2 脚本**：NPC/任务/事件 JS 热重载（改文件 → reload → 新内容生效 + 插件命名空间共存，L2ScriptReloadTest）
- [x] **L3 逻辑/插件**：模块 classloader 替换 + 按实体渐进重载（插件 reload = unload + 换代版本门 + 渐进重载）
- [x] **L4 进程兜底**：DRAINING + 增量 FLUSH + 重启 + 恢复（RestartService 接线真实组件，L4RestartE2ETest）
- [x] 主动重开三件套：增量 FLUSH（CharacterSaveQueue.flushAllSync）+ WZ 文件缓存（复用 WzCache）+ 上下文恢复（fromData 原地复活）
- [x] 主动重开 ≠ 全量落盘：只 FLUSH 脏数据（红线 17）

### 3. 频道间交互三机制

> 铁律：**共享状态绝不做"每个频道各持一份、靠同步保持一致"**（数据发散、互相覆盖的根源）。M4 单进程内全部进程内实现，但接口从第一天按"不假设进程内"设计（接口先行、分布式后置）。

- [x] **状态（单一属主）**：共享状态只在一个地方持有真值（coordinator），频道需改则发消息、改完来读
  - [x] 好友（buddylist V6 表，BuddyHandler 持久化）
  - [~] 公会 / 排行 / 商店资金 / 活动数据 —— **只落 `SingleOwnerStore` 通用基础设施 + 公告/商店 counter 验证**；公会/排行**完整玩法不在 M4**（M5 随 Web 控制台配套）
- [x] **消息（消息总线）**：悄悄话=发目标频道、喇叭=广播、CC 请求=发目标频道；总线不存状态，只负责送达
- [x] **玩家定位（定位表）**：coordinator 维护 player → 频道；CC、悄悄话、加好友前先查"人在哪个频道"
- [x] 悄悄话 / 加好友 / CC / 活动公告走三机制
- [~] 喇叭 —— **只有活动公告广播（NoticeMessage → SERVERMESSAGE）**；**喇叭道具 handler（GENERAL_CHAT 点喇叭消耗道具）未做**，留后续
- [x] CC 迁移（一机制两用）：功能（换频道）+ 兜底（升级前把玩家挪走 → 重启 → CC 回来）

### 4. 可靠性（业务层保证）

- [x] 持久化队列（投递成功才 ack，进程崩了重发）
- [x] 接收方幂等去重（消息带全局 ID）
- [x] 单一属主序号（同一逻辑流按序投递）
- [x] 三者组合 = 语义上的恰好一次（CC 迁移不掉数据、不重复的核心）

### 5. 配置中心形态（4.6.5）

- [x] 真值在 DB（`param_conf` 表），管理进程内配置服务读它、持有版本号
- [x] 各进程启动拉取一次，之后经 EventBus 订阅变更（M4 单进程 = 进程内订阅；M6 换 TCP 长连接，接口不变）
- [x] 变更链路：admin 控制台改配置 → 写 DB → 版本号 +1 → 广播 → 各频道重读

## 完成范围诚实标注（后面开发必读）

M4 验收标准 6 项全勾，但**部分子项是简化/骨架形态**，避免误读为"全量完成"：

| 项 | 完成形态 | 留待 |
|---|---|---|
| **插件 HTTP 路由 / AI Tool 贡献点** | 7 类贡献点类型定义 + 接线 5 类（packet/tick/event/script-namespace/logic-system） | HTTP（Micronaut 编译期 DI 冲突）/ AI（AiServices 重建成本）**明确不接线**，M5 随管理进程插件宿主做 |
| **加好友** | BuddyHandler + buddylist V6 持久化 + 确认/拒绝/删除走三机制 | `buddyListPacket` 是简化版（数量写死 0，未读真实 DB 列表回填）；v83 BUDDYLIST 包逐字节布局未核对 |
| **喇叭** | 活动公告广播（NoticeMessage → SERVERMESSAGE） | 喇叭道具 handler（点喇叭消耗道具）未做 |
| **CC 迁移** | 定位更新 + 清地图 + 会话注销（单进程内"重连"= 同进程） | 真正跨频道端口重连是 M6（接口已按不假设进程内设计） |
| **公会/排行/商店资金** | SingleOwnerStore 通用存储基础设施 + 公告/商店 counter 验证 | 完整公会/排行玩法不在 M4，M5 配套 Web 控制台 |
| **可靠总线序列化** | PayloadCodec.MARKER（单进程投递真实对象）+ 接收侧去重内存化 | 跨进程 JSON 序列化 + 接收侧去重落 bus_stream 表是 M6 |
| **WZ 文件缓存** | 复用既有 WzCache（未新增验证） | — |

**遗留技术债**：`TradeE2ETest` 偶发失败（`Thread.sleep(100)` 计时脆弱，非功能回归）——未修复，全量负载下偶发超时。

## 风险与注意

- **插件 classloader 可见性边界**是最易踩的坑：加载/遮蔽稳定层类即 CCE，靠架构测试兜底。
- **共享状态单属主铁律**：任何"每频道各持一份靠同步"的实现都违反此铁律（数据发散根源）。
- **可靠性三件套缺一不可**：持久化队列 + 幂等去重 + 单一属主序号 = 恰好一次，CC 迁移的正确性全押在这里。
- M4 是三机制进程内形态，**接口不假设进程内**（M6 换网络实现，接口不变）。
