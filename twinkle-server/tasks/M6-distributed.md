# M6：分布式（大区/频道独立进程）

> 对应 [ARCHITECTURE.md](../../ARCHITECTURE.md) 第四节 4.2-4.6（角色/进程/拓扑/内部通信/分进程组件全图）、4.7（CC 迁移）、第十一节 M6。
>
> 状态：未开始 ｜ 前置依赖：M5 ｜ 影响模块：`bootstrap`、`coordinator`、`net-netty`（内部通信）、`channel`、`http-api`

## 目标

分布式：大区/频道独立进程、world-coordinator、CC 迁移、消息总线。

**交付**：多机部署、玩家换频道、升级滚动。

## 任务清单

### 1. 进程边界落地（最高原则 4.1）

- [ ] `--profile=split-channel` / `split-realm` 真正拆进程（M0 已定义，此处网络化）
- [ ] 同一套代码：`single` ↔ `split-*` 配置切换，进程内实现 ↔ 网络实现
- [ ] 通信接口与进程内是同一套（接口不假设进程内外，M0 起已如此设计）
- [ ] 2C2G 强制单进程（红线 15）：split 仅限大内存机器 / 多机

### 2. 内部通信机制（4.5，零新依赖）

- [ ] 复用 net-netty：每个进程 Netty 客户端 + 服务端，与 coordinator TCP 长连接
- [ ] 自定义二进制帧 `[帧头 | 消息类型 | 消息ID | 负载]`（M1 已定义帧接口，此处实现）
- [ ] 不用 HTTP（内部进程通信不用 HTTP；HTTP 专用于对外 API）
- [ ] 进程内 EventBus ↔ Netty 网络帧（同一接口，配置切换）

### 3. coordinator（共享状态代理 + 定位表 + 路由）

- [ ] coordinator 无状态（定位表靠 channel 上报 + 心跳重建，不需要主备选举）
- [ ] 内建注册中心：channel → coordinator 单向上报（频道ID、host:port、在线状态）+ 心跳
- [ ] coordinator 崩了无状态重启 → channel 重连重新上报 → 定位表自动重建
- [ ] 内建配置中心（跨进程形态，4.6.5）：DB 真值 + 版本号 + TCP 长连接推送
- [ ] 消息路由：悄悄话 = 频道A → coordinator（查定位表）→ 转发频道B；广播（喇叭）= 群发所有频道
- [ ] 星形拓扑，coordinator 单点

### 4. 共享状态单一属主（跨进程）

- [ ] 共享状态真值在 DB（coordinator 只是读写代理）
- [ ] 频道需改则发消息、改完来读（单一属主铁律跨进程保持）
- [ ] 公会、好友、排行、商店资金、活动数据（进程内形态 → 网络实现，接口不变）

### 5. 第三方 HTTP 跨进程取数（4.6.6，把约束物理化）

- [ ] ① 查 DB（主路）：市场记录、商店快照、角色存档
- [ ] ② 经 service 接口 → RPC 到频道进程（复用消息总线帧）
- [ ] ③ 事件驱动快照：频道进程推变更 → 管理进程只读镜像 → HTTP 读镜像
- [ ] 镜像单向、只读，禁止经镜像回写

### 6. CC 迁移跨进程

- [ ] 老频道 flush 状态 → 目标频道加载 → 客户端重连（v83 客户端换频道 loading 界面）
- [ ] 可靠性三件套（M4 已实现，此处跨进程）：持久化队列 + 幂等去重 + 单一属主序号 = 语义恰好一次
- [ ] CC 迁移不掉数据、不重复
- [ ] 兜底用法：升级滚动（玩家换频道 → 重启 → CC 回来）

### 7. 升级滚动

- [ ] 频道逐个滚动升级（一个频道崩了不连累全服，故障隔离）
- [ ] 升级过程玩家"闪一下"回来

## 验收标准

- [ ] 多机部署（`split-*` 档跑通，single 档性能不退化）
- [ ] 玩家换频道（CC 迁移跨进程不掉数据、不重复）
- [ ] 升级滚动（频道逐个重启，服务不中断）
- [ ] coordinator 无状态重启后定位表自动重建
- [ ] 悄悄话 / 喇叭 / 加好友跨频道走消息总线

## 风险与注意

- **诚实面对物理代价**（4.1）：拆进程不是免费——多 JVM 常驻开销 + 共享数据变"每进程各一份 + coordinator 同步"。**2C2G 强制单进程**，split 仅限大内存机器 / 多机。
- **隔离是买故障隔离，不是买性能**：单机 20 频道若无隔离诉求，`--profile=single` 单进程抗满。
- **可靠性三件套不能省**：本地回环更快但不更可靠，"进程崩了"照样发生。
- **镜像禁止回写**（单一属主铁律）：写操作一律经 service 接口 RPC 到频道进程。
- **HTTP 分进程后"物理隔离"**：两进程不共享内存，HTTP 想碰频道数据都碰不到，只能走三路。
