## 目标

游戏逻辑**重写**为状态/逻辑分离，参考项目（北斗）作 parity 真值，行为对齐。这是工作量最大的里程碑。

**交付**：状态/逻辑分离重写，录包回放 / 双跑对照行为对齐参考项目。

## 任务清单

### 1. domain-game：纯数据模型（稳定层）

- [ ] 游戏对象模型：Character / MapleMap / Item 等，**纯数据**（版本化 schema）+ 索引/服务
- [ ] **游戏对象不进容器**（红线 4）：手动 new，容器只管基础设施 + Service
- [ ] 稳定层：协议、数据模型、状态索引、核心机制（不参与重载，被引用）
- [ ] `characters` 存档结构兼容：~60 列 + keymap/skills/queststatus/inventory 结构不变（红线 3）
- [ ] MySQL `newmaple` 库兼容：表结构不改，扩展走 migration `ADD COLUMN`（红线 2）

### 2. 状态/逻辑分离

- [ ] 可替换层：游戏逻辑系统（systems），经接口访问稳定层，**绝不反向依赖**
- [ ] 可替换层**不得引用游戏内存对象的具体类**（只能用接口或数据投影，防 CCE，红线 8/11）
- [ ] 可替换层**不得持有跨操作状态**（逻辑无状态化，红线 8/12）
- [ ] 逻辑无状态化：从索引读 → 计算 → 写回，不持有跨操作状态（热重载安全前提）
- [ ] 核心机制：移动、战斗、交易、任务、背包（重写为状态/逻辑分离形式）

### 3. wz-provider（WZ 解析）

- [ ] WZ 解析
- [ ] WZ 文件缓存（预编译到磁盘，启动读文件省重解析——秒级重开在 2C2G 上的关键，M0 已验证，此处接入真实数据）

### 4. domain-script（GraalVM JS）

- [ ] 脚本引擎接入（org.graalvm.js:js 独立库 + EnableJVMCI 全速，M0 已验证）
- [ ] 宿主对象契约（cm/qm/em/rm/im）不变（脚本兼容性）
- [ ] L2 热更新：NPC/任务/事件 JS 重读文件即生效，统一 ScriptManager + reload 入口
- [ ] 脚本重载不影响进行中的脚本执行

### 5. channel（频道初版）

- [ ] 频道、玩家在线表、CC 迁移（M4/M6 完善，此处打通进图）
- [ ] 玩家进图（M1 的选角打通到进图）
- [ ] 游戏 tick 单线程框架（tick 帧边界暂停 = 热重载换点干净）

### 6. parity 验证

- [ ] 录包回放：参考项目录包 → 本实现回放 → 行为对齐（用 M0 基建）
- [ ] 双跑对照：同一输入跑参考项目与本实现，输出对齐
- [ ] 行为对齐参考项目（关键机制逐一比对）

## 验收标准

- [ ] 客户端登录、进图
- [ ] 移动 / 战斗 / 交易 / 任务 / 背包行为对齐参考项目（parity 通过）
- [ ] 存档读写在 `newmaple` 兼容结构上正确（老存档可读）
- [ ] 状态/逻辑分离架构测试通过（可替换层引用纪律）
- [ ] 脚本热重载生效（改 JS 即生效）

## 风险与注意

- **别"顺手改进"协议/存档**：v83、`newmaple`、存档格式三条兼容红线（1/2/3）在重写期最容易破，靠 parity 测试兜底。
- **交易等跨 tick 操作**天然是热重载风险点，M0 起按"单实体安全点"设计（5.3），此处落地为逻辑。
- **游戏对象不进容器**（红线 4）：重写期最容易退化成"顺手放进容器省事"。
- 管理侧仍**不得依赖 domain-game**（依赖单向无环）。
