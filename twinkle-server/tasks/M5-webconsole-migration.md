## 目标

Web 控制台（替代 JavaFX）、单库迁移、上线切换。

**交付**：控制台、单库迁移、切换。

## 任务清单

### 1. Web 控制台（admin）

- [ ] admin 模块：Web 控制台 + 运维 API（北斗式，替代 JavaFX，JavaFX 明确移除）
- [ ] 控制台能力：频道状态、在线玩家、配置热改（走配置中心变更链路）、运维操作
- [ ] 运维操作经 service 接口（不得直踩游戏内存）
- [ ] admin 并入管理进程（低频、无状态、只经 service 接口，为隔离单独付 JVM 不值）

### 2. 单库迁移

- [ ] 老库（参考项目）→ 新结构迁移：migration 管结构、seed 管内容
- [ ] 表结构不改，扩展走 migration `ADD COLUMN`（红线 2：禁止单条 ALTER 串接多列）
- [ ] `characters` 存档结构兼容迁移（~60 列 + keymap/skills/queststatus/inventory 结构不变，红线 3）
- [ ] 数据验证：迁移后老存档可读、行为对齐参考项目

### 3. 上线切换

- [ ] `--profile` 装配的正式档位确认（默认 `single`）
- [ ] 日志规范（log4j2，`log.error("描述", e)`，禁用 `e.printStackTrace()`，红线 9）
- [ ] 切换脚本 / 步骤
- [ ] 灰度 / 回滚路径（CC 兜底：升级前挪玩家 → 重启 → CC 回来）

## 验收标准

- [ ] Web 控制台可用（频道状态 / 在线玩家 / 配置热改 / 运维操作）
- [ ] 单库迁移成功（老库数据无损、老存档可读）
- [ ] 上线切换完成（默认档跑通，回滚路径验证过）

## 风险与注意

- **迁移别破兼容红线**：`newmaple` 表结构与 `characters` 存档结构三条兼容红线（2/3）在迁移期最易破，迁移后必须 parity 验证。
- **控制台运维操作不得直踩游戏内存**：经 service 接口，同 HTTP/AI 约束。
- **主动重开 ≠ 全量落盘**（红线 17）：上线切换靠 CC 兜底 + 增量 FLUSH，不是"等几分钟停服"。
